```markdown
# CS Learning Hub：AI 協作規則

## 專案目的
為資工初學者提供繁體中文知識筆記。讀者應能理解概念、追蹤範例，並自行練習。新文章必須能沿用同一套版型與流程。

## 結構與唯一來源
- `content/articles.json`：文章清單、分類、搜尋關鍵字、章節及程式碼，是內容唯一來源。
- `templates/article-template.json`：新增文章用的單篇物件範本，不會自動公開。
- `scripts/build.mjs`：產生共用導覽、首頁、目錄、前後篇與文章 HTML。
- `assets/css/style.css`：全站設計；`assets/js/`：首頁搜尋與篩選。
- 建置時為 CSS、主程式與匯入的搜尋模組加入內容雜湊版本，讓更新後的正式站載入最新檔案。首頁搜尋初始化必須選取 `input#search`，避免文章的同名章節觸發首頁程式。
- `dist/`：可直接部署的產物，已納入交付；不可手動修改。變更來源後重新 build，建置會先清除舊產物，避免殘留已移除文章。
- `tests/`：內容完整性、內部連結、搜尋及文章程式範例測試。
- `docs/`：部署、測試紀錄與繳交範本；`.github/workflows/`：持續檢查。

## 技術與限制
使用 HTML、CSS、原生 JavaScript。Node.js 22 以上只用於產生網頁、測試和本機預覽，網站本身沒有後端、不需套件安裝。不要任意加入框架、CDN、字型下載、追蹤器或資料庫。不要修改父資料夾或 `sources/` 的同步檔案。

## 視覺與可用性
白色／淺灰背景，深藍文字與青綠重點色。沿用 CSS 變數、卡片、文章側欄與頁尾。繁體中文為主，首次出現的專業名詞附英文。桌面首頁三欄、手機單欄；內頁桌面側欄、手機橫向導覽。正文行高約 2，程式碼可橫向捲動。保留語意標籤、單一 h1、正確標題階層、跳至內容連結、焦點提示、搜尋標籤、aria-current 與篩選 aria-pressed；不能只用顏色傳遞資訊。

## 新增文章格式
1. 複製 `templates/article-template.json` 的物件並填寫所有欄位，加入 `content/articles.json` 陣列。
2. `slug` 使用唯一小寫英文與連字號（例如 `queue`）；產物路徑固定 `dist/pages/<slug>.html`。章節 id 同樣使用小寫英文與連字號，篇內不可重複。
3. `number` 使用唯一兩位數顯示編號；`minutes` 為正整數估計閱讀分鐘；`glyph` 是首頁卡片的簡短圖示符號（最多八字，未設定則用 ◇，不要依照 slug 硬編碼）；`category` 優先沿用現有分類，必要時新增。首頁分類從資料自動產生。
4. 每篇至少四節，最後一節固定 `id: "practice"`。內容依序涵蓋核心概念、完整範例、應用或推導、效率／誤區、練習及解答。
5. 資料結構說明時間與空間複雜度、適用前提與邊界情況；數學文章明列假設、推理、結論，不能用測試代替證明。
6. `html` 只放可信、人工可讀的靜態內容片段，不能含 script、事件屬性、遠端嵌入或 javascript: 連結。不要將使用者輸入拼接成 HTML。程式碼放 `code` 欄位，並以 `language` 明確標示程式語言（例如 `JavaScript` 或 `C++`）；產生器會跳脫程式碼文字並使用正確語言標籤。
7. 練習解答使用 `<details><summary>查看解答</summary>…</details>`，讓讀者能先自行思考。圖解需有文字說明；外部素材應標示來源與授權，不編造引用。
8. 所有站內路徑採相對路徑，禁止以 `/assets/` 等根路徑引用，以支援 GitHub Pages 的 repository 子路徑。

## 修改流程與驗收
先讀本文件、範本與既有文章，優先改資料或共用元件。執行 `npm run check`；新增可執行程式範例時，在 `tests/site.test.mjs` 加入具體預期輸出與邊界測試。確認首頁卡片與 glyph、搜尋、分類、目錄及前後篇同步更新。使用 `npm run dev`，手動檢查桌面與 375px 手機寬度、鍵盤操作、空搜尋結果及 JS 停用時的閱讀。連同來源與最新 `dist/` 一起提交。不要提交憑證、個資或假造的部署成功紀錄。

## 可直接使用的新增提示
「請先閱讀 AGENTS.md，依 templates/article-template.json 新增 Queue 佇列文章。包含 FIFO、enqueue/dequeue、實作、複雜度、常見誤區及練習。更新資料與必要測試，重新產生 dist，執行 npm run check 並回報結果。」
```

5. 規則如何幫助 AI 新增內容

若之後要新增 Queue 佇列文章，AI 可以先閱讀 AGENTS.md，依照文章範本填入標題、分類、摘要、關鍵字、概念、範例、效率分析與練習。文章資料加入 content/articles.json 後，共用產生器會自動建立文章頁面，並同步更新首頁卡片、分類、搜尋與導覽。接著執行檢查並確認手機版面，就能沿用相同樣式繼續擴充，降低每次重新設計及遺漏步驟的機會。

本次三篇文章皆採相同資料格式及共用版型，示範同一套規則如何應用在資料結構與數學主題。網站由 AI 協助實作，我透過規則、內容檢閱與測試流程維護成果。
